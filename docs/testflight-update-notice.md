# Optional TestFlight update notice

The app checks one shared HTTPS manifest at /api/data/releases/testflight-v1.json through the existing data gateway. The initial manifest is disabled: no build is advertised, especially no Scott-only build. It has no secrets, tester identity, executable code or destination URL. Installed version and globally monotonic build are compared: the target version cannot be older and its build must be greater. A verified sandbox AppTransaction matching Hub Ball's bundle ID and App Store ID is required; an unavailable/unverified/production transaction silently suppresses the notice. This does not identify a tester's group.

The broad target must explicitly be available to all supported groups, currently Hub Ball Internal and Family, on iPhone and iPad. Private releases never change it. The CLI scripts/publish_beta_release.py --build NUMBER performs fresh read-only Apple queries with the existing private Mac release credentials, verifies VALID/unexpired state and both actual group/build listings and beta states, and reads the matching archive/receipt to verify universal device support and minimum OS. Unknown groups, extra API pages, private/missing builds or any failed check abort before writing. It prepares a local file only: no assignment, beta submission, notification, push or deployment. --disable writes a disabled manifest for bootstrap/rollback. Reverify the target at least daily if reminders should stay active: the client suppresses confirmations 24 hours old, future timestamps, expired or unsupported targets. This intentional quiet timeout avoids indefinitely trusting revoked or expired access.

The client bypasses HTTP/local caches, uses an ephemeral session with redirects disabled, accepts at most 16 KiB, schema1/exact bundle and fixed group/device allowlists, and never saves the target offline. Network/decode/eligibility errors remove the candidate without an error message or blocking app use. Checks occur on launch and at most every 30 minutes on foreground. Dismiss suppresses that exact version/build for seven days and the remainder of the process; a newer target can appear. Open TestFlight to update also snoozes and attempts https://testflight.apple.com/a with UIKit's universalLinksOnly option. Apple publishes /a in TestFlight's associated-domain paths. The option only opens an installed app associated with the HTTPS URL; a false completion shows explicit “TestFlight didn’t open” manual instructions. A successful completion presents no instructions. No public invitation, enrollment code, undocumented URL scheme or app-specific page promise is used. The external help link in the failure sheet is https://testflight.apple.com/, labeled Apple help. The physical iPhone has TestFlight installed and launching its bundle was verified, but the notification-to-TestFlight universal-link gesture is not yet verified on that phone; simulator injected success/failure checks are not physical proof.

The inline notice waits for onboarding and the process's launch story to finish dismissing. It hides during the Separated by One sheet, Postseason, Stories, hitter, settings, update instructions and inactive scenes. Launch-story consumption belongs to AppModel. Story autoplay, replay, dismissal and library reopening remain intact. Dynamic Type keeps the notice copy readable in a bounded scroll area at accessibility sizes while Dismiss and Open TestFlight to update remain visible; instructions scroll, with Done available in the toolbar.
