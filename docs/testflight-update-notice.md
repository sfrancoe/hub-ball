# Optional TestFlight update notice

The app checks one shared HTTPS manifest at /api/data/releases/testflight-v1.json through the existing data gateway. The initial manifest is disabled: no build is advertised, especially no Scott-only build. It has no secrets, tester identity, executable code or destination URL. Installed version and globally monotonic build are compared: the target version cannot be older and its build must be greater. A verified sandbox AppTransaction matching Hub Ball's bundle ID and App Store ID is required; an unavailable/unverified/production transaction silently suppresses the notice. This does not identify a tester's group.

The broad target must explicitly be available to all supported groups, currently Hub Ball Internal and Family, on iPhone and iPad. Private releases never change it. The CLI scripts/publish_beta_release.py --build NUMBER performs fresh read-only Apple queries with the existing private Mac release credentials, verifies VALID/unexpired state and both actual group/build listings and beta states, and reads the matching archive/receipt to verify universal device support and minimum OS. Unknown groups, extra API pages, private/missing builds or any failed check abort before writing. It prepares a local file only: no assignment, beta submission, notification, push or deployment. --disable writes a disabled manifest for bootstrap/rollback. Reverify the target at least daily if reminders should stay active: the client suppresses confirmations 24 hours old, future timestamps, expired or unsupported targets. This intentional quiet timeout avoids indefinitely trusting revoked or expired access.

The client bypasses HTTP/local caches, uses an ephemeral session with redirects disabled, accepts at most 16 KiB, schema1/exact bundle and fixed group/device allowlists, and never saves the target offline. Network/decode/eligibility errors remove the candidate without an error message or blocking app use. Checks occur on launch and at most every 30 minutes on foreground. Later suppresses that exact version/build for seven days and the remainder of the process; a newer target can appear. Update also snoozes and opens dismissible instructions: open TestFlight, select Hub Ball, tap Update. The only external link is https://testflight.apple.com/, explicitly labeled Apple help. No undocumented TestFlight scheme or unverified direct navigation promise is used. Physical TestFlight navigation is not claimed; the supported manual steps and official HTTPS help are the safe fallback.

The inline notice waits for onboarding and the process's launch story to finish dismissing. It hides during the Separated by One sheet, Postseason, Stories, hitter, settings, update instructions and inactive scenes. Launch-story consumption belongs to AppModel. Story autoplay, replay, dismissal and library reopening remain intact. Dynamic Type keeps the notice copy readable in a bounded scroll area at accessibility sizes while Update/Later remain visible; instructions scroll, with Done available in the toolbar.

## Deployment gate

The smallest production activation scope is: add releases/testflight-v1.json to the existing netlify/functions/app-data.mjs allowlist and its 16 KiB/schema/no-store response branch; publish the generated disabled data/releases/testflight-v1.json; and add the exact /data/releases/testflight-v1.json no-store header in netlify.toml. These three files can ship independently of the private native build. The gateway reads data from GitHub main at runtime. Publishing a later verified broad target is a data-file update generated by the CLI; private uploads must never invoke it. No function, service, credential, tester group, access policy or dependency is created. The existing deploy would update the same Netlify site at api.autumnlane.io/red-sox.netlify.app. Approval for this server deployment is still required; no source push or deployment is performed by this implementation task.

Until that deployment, production returns 404 for this optional endpoint, so the review binary runs normally with no notice. Simulator fixtures exercise the complete enabled UI without publishing a fabricated broad target. A real notice cannot appear to Scott in the new private binary until a later, greater broad build is available; this is expected.
